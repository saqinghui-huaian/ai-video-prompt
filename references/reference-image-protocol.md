# 参考图引用协议 · `{{Image N}}` 到底是什么

> 这是本技能最容易出错、也最容易被忽略的一层。
> 提示词里的 `{{Image N}}` 是**纯文本占位符**，它不会自己找到图片；真正决定第 N 张图是哪张的，是你在生成节点里**挂图的先后顺序**。两者错位，参考图就白挂——模型会按错误的图去锁脸、锁场景。

本文件解决四件事：**怎么编号、每张图写什么、缺图怎么办、怎么核对**。

---

## 一、编号规则：编号 = 挂载顺序，不是角色顺序

| 规则 | 说明 |
|---|---|
| 顺序即编号 | 在节点里第 1 个拖入的图 = `{{Image 1}}`，第 2 个 = `{{Image 2}}`。你调的挂载顺序变了，提示词里的编号必须跟着改。 |
| 从 1 连续 | 不允许 `Image 1` 之后直接跳 `Image 3`。留空号会让模型把中间那张当成不存在的槽位。 |
| 一图一号 | 同一张图不要重复挂两次占两个号；需要强调某张图时，在段 2 用文字加重，不要复制槽位。 |
| 先主体后环境 | 多数模型对靠前的图权重更高。推荐挂载序：**角色 → 场景 → 道具 → 影调/风格参考**。 |
| 角色与场景不同图 | 不要把人物和场景拼成一张图传入。模型会把场景的色温与光位烧到人物脸上，且无法分别声明边界。 |
| 建议 ≤ 4 张 | 超过 4 张时模型对每张的注意力被稀释，冲突概率大于收益。真要更多，拆成两段生成或先合成一张美术板。 |

**编号不需要手写**：`scripts/build_prompt.py` 按列表位置自动推导 `Image N`，配置里写 `slot` 只是给人和模型看的说明，写错反而报错。手写规格书时仍建议显式标出编号，便于对账。

**反例**：提示词写「`{{Image 1}}` = 场景图」，但节点里第 1 张挂的是人物图 → 模型拿人物图去当场景，空间结构全崩。
**正确做法**：先定挂载顺序，再按顺序写段 2；顺序变了就重写编号，不要指望模型自己猜。

## 二、每张图必写三段

一行一图，三段缺一不可：

```
{{Image N}} = <这张图是什么>：提供 <它负责锁定的信息>；不提供 <它不该干涉的信息>；冲突以正文为准。
```

| 段 | 作用 | 漏写的后果 |
|---|---|---|
| **是什么** | 给模型一个人能看懂的名字（「主角 18 岁定妆照」「便利店外景空镜」），不要写文件名 | 模型分不清哪张图干什么 |
| **提供什么** | 明确它锁定的维度：脸 / 体型 / 服装款式 / 空间结构 / 物件位置 / 光位 / 色调颗粒 | 模型自由发挥，参考图等于没用 |
| **不提供什么** | 明确它**不**锁的维度：机位、景别、构图、表情、姿态、光照方向、人物 | 参考图反向锁死机位，五镜变成同一张图的五次翻拍 |

**冲突裁决句必须写**：`冲突以正文为准。`（或 `各镜机位与状态由正文定义。`）这一句是防止参考图压制分镜的唯一手段。

`withholds` 与 `conflict` 是**必填**，不能用一句「以正文为准」的备注顶替：备注写「取景以正文为准」时，模型仍不知道光与姿态归谁管。三段缺任一段，`build_prompt.py --check` 会直接判 FAIL。

## 三、按图类型选句式（照结构，不照抄句子）

下表给的是**结构**。写的时候把你自己的题材名词填进去，不要原样搬运原型里的「李默」「小卖部」「CRT 收银终端」。

| 图类型 | 提供 | 不提供 | 冲突裁决 |
|---|---|---|---|
| **角色 / 主体图** | 面部特征、体型、发型、服装款式与颜色 | 表情、姿态、机位、光照方向、场景 | 本场状态（表情、动作、衣着整齐度）以正文分镜为准 |
| **场景 / 空间图** | 空间结构、关键物件位置、材质、年代质感、光位 | 机位、景别、构图、画面里有没有人 | 各镜机位由正文定义 |
| **道具图** | 外形、材质、颜色、磨损与文字细节 | 持握方式、出现位置、与谁同框 | 出现时机与持握方式以正文为准 |
| **影调 / 风格参考图** | 色调、对比、颗粒、光比 | 构图、主体身份、场景内容 | 只借影调，不借画面内容 |
| **姿态 / 动作参考图** | 身体姿态、动作幅度 | 人物身份、服装、场景 | 人物身份以角色参考图与正文为准 |

**只写一条边界是不够的**。只写「仅提供面部参考」而不写「不提供什么」，模型仍会把参考图的正面平光、白背景、半身构图带进每一镜。

## 四、缺图怎么办：降级矩阵

参考图不是必须项。张数不同，段 2 与正文写法都要跟着变：

| 图数 | 段 2 写法 | 正文必须补什么 | 风险 |
|---|---|---|---|
| **0 张** | 保留 `[参考图锚定]` 标题，正文写一行：`本片不使用参考图：主体外观与空间结构以段 1 与正文文字描述为准。` | 主体**首次出现时**写一次外观锚点（发型 / 体型 / 服装 / 显著特征），之后只用名字或代词；场景在段 3 用方位词锚死 | 跨镜漂移风险最高。同一角色在不同镜可能换脸，建议先出设定图 |
| **1 张（仅角色）** | 只写角色行，不写场景行 | 段 1 `set_dressing` 写到可辨识物件级，段 3 方位锚点写全 | 场景结构易崩、光位不统一 |
| **1 张（仅场景）** | 只写场景行 | 主体外观写进段 1 或正文首镜 | 角色跨镜换脸 |
| **2 张（角色 + 场景）** | 标准式，两行 | 无需额外补 | 低，最稳的配置 |
| **3–4 张** | 逐行，每行都要三段 | 注意图间互相污染：角色图的平光不要盖掉场景图的窗光 | 低，但要检查风格参考图没抢戏 |
| **> 4 张** | 先合并或拆片，不要硬堆 | — | 高。模型兼顾不了，编号也容易错 |

**0 张时不要删掉段 2 的标题**。五段结构是骨架，缺内容就写「不使用」，让结构保持可核对；直接删段会让后续质检漏项。

## 五、必附对账行

任何产出都必须把编号映射回挂载顺序，写在参数建议里：

```
参考图挂载顺序（与节点内图片排列一致，顺序错则编号全错）：
  Image 1 = 主角 18 岁定妆照（锁脸与服装）
  Image 2 = 场景外景空镜（锁空间与光位）
```

没有这一行，用户无法核对，等于把出错概率留给运气。

## 六、图生图链路：设定图 → 参考图

要跨镜、跨年龄保持一致，正确链路是三步，不要跳步：

1. **先出设定图**（走辅助模式 `references/image-prompt-guide.md`）：角色定妆照 / 场景空镜 / 道具三视图，单张、干净背景、正面平光。
2. **把设定图挂进视频节点**，顺序按第一节推荐（角色在前）。
3. **按挂载顺序写段 2**，声明每张图的边界，再写正文。

跨年龄复用同一张脸时，追加 `Same person as the attached <年龄> character sheet`，并把年轻版设定图作为独立槽位挂入，不要和当前版本混成一个号。

## 七、六种常见失败模式

| 现象 | 原因 | 修法 |
|---|---|---|
| 五镜全是同一构图 | 场景图没写「不提供机位」 | 补冲突裁决句 |
| 角色每镜换脸 | 角色图挂了但正文没回指，或图权重被场景图压过 | 角色图放第 1 位；正文首镜写一次 `{{Image 1}} 中的 <名字>` |
| 光照方向不一致 | 参考图光位与段 1 `lighting` 冲突却没裁决 | 段 1 写死光位，段 2 写「光位以段 1 为准」 |
| 人物脸被压成场景色 | 角色与场景合成一张图传入 | 拆成两号 |
| 道具形状每镜变 | 只有文字描述、没有道具图 | 补三视图并单独占号 |
| 模型无视参考图 | 编号跳号、或提示词编号与挂载顺序不一致 | 按第一节重新连续编号并核对 |

## 八、自查四问（写完段 2 逐条问）

1. 编号从 1 连续、无跳号、与将要挂载的顺序逐一对得上吗？
2. 每张图都写了「提供什么」「不提供什么」两句吗？
3. 有「冲突以正文为准」这类裁决句吗？
4. 张数落在降级矩阵的哪一格，正文是否补了对应的兜底描述？

四问全过，才算把图片引用这件事做对。

## 九、三分钟自验：确认平台到底怎么认编号

「编号 = 挂载顺序」是从 TapNow 视频节点的实际行为反推出来的规则。平台改版或换平台（Seedance / 可灵 / 即梦）后，认法可能不同。**不确定时用这一次低价测试确认，比反复出废片划算**：

1. 准备两张差别极大的图：A = 一张明显是人物正脸，B = 一张明显是空房间。
2. 先挂 A 再挂 B，提示词写 `{{Image 1}} = 房间`、`{{Image 2}} = 人物`（**故意写反**）。
3. 用最低分辨率、最短时长生成一次。
4. 看结果：
   - 出来的是「按提示词文字」的人物 + 房间 → 平台按**文字语义**匹配，编号不影响，此时编号只需连续即可；
   - 出来的人脸是 A、房间是 B（即按挂载顺序）→ **编号 = 挂载顺序**成立，本文规则全部适用；
   - 只认其中一张、另一张被忽略 → 平台有上限或只取首图，减少到 1–2 张并重测。

把结论记在项目里。换平台时重跑一次，不要凭经验假设。
